## 1. Описательная часть (Геймплей и User Experience)

### 1.1. Концепция и фестивальный сценарий
**Flexy Way** — это интерактивная игра-раннер для больших экранов (медиафасады, ТВ-панели, проекторы на фестивалях и выставках), где в роли геймпада выступает собственный смартфон любого зрителя без необходимости скачивать какие-либо приложения.

```
 [ Зритель на фестивале ] 
          │
          ▼  (Сканирует QR-код камерой смартфона)
 [ Мобильный пульт в браузере (4G/5G) ]
          │  ~15-30 ms через Cloud MQTT
          ▼
 [ Большой экран с 3D-игрой (Three.js) ]
```

---

### 1.2. Пользовательский путь (Onboarding Flow)
1. **Экран ожидания**:
   * На главном экране отображается окно с динамическим QR-кодом и PIN-кодом комнаты (`FLEXY`).
   * Игра находится в режиме демонстрации.
2. **Бесшовный вход**:
   * Пользователь наводит камеру смартфона на QR-код $\rightarrow$ в браузере телефона открывается пульт `controller.html?room=FLEXY`.
   * Экран мгновенно распознает подключение: статус-индикатор загорается зеленым, модальное окно QR-кода автоматически закрывается, игра готова.
3. **Калибровка**:
   * Игрок держит смартфон экраном вверх, направляет передний торец на экран и нажимает кнопку **«🎯 КАЛИБРОВАТЬ ЦЕНТР»**.
   * Текущее положение телефона фиксируется как нейтральная точка $(0, 0)$.

---

### 1.3. Игровая петля (Core Gameplay Loop)
* **Персонаж**: Неоновый парящий 3D-куб в нижней части экрана.
* **Цель**: Собрать как можно больше золотых монет и продержаться как можно дольше, не столкнувшись с падающими геометрическими фигурами.
* **Препятствия**: Сверху нескончаемым потоком падают различные 3D-фигуры (тетраэдры, октаэдры, призмы, цилиндры), хаотично вращаясь в пространстве.
* **Воронка и расталкивание (Funnel & Magnetic Physics)**:
  * Препятствия не падают скучной сеткой: между ними действует физика взаимного магнитного отталкивания, создавая динамические коридоры и «карманы» для маневров.
  * У краев экрана фигуры отскакивают от невидимых стен.
* **Нарастание сложности (Dynamic Difficulty Scaling)**:
  * Каждые 2 секунды скорость падения увеличивается на 20%.
  * Частота спавна новых волн сокращается, создавая плотный поток препятствий.
* **Сбор монет**:
  * Каждая пойманная монета дает вспышку очков, инкрементирует счетчик и отправляет **вибро-отдачу (Haptic feedback)** на телефон игрока.
* **Game Over и Рестарт**:
  * При касании любого препятствия куб игрока эффектно разлетается на частицы с трехмерным импульсом.
  * На телефон отправляется тревожный вибро-сигнал аварии.
  * Показывается финальный результат «ГАМОВЕР: Собрано монет: N».
  * Через 3 секунды игра автоматически перезапускается для нового раунда.

### 1.4. Режимы управления на смартфоне
В пульте предусмотрен переключатель режимов под разные условия:

| Режим | Как работает | Для кого / когда |
| :--- | :--- | :--- |
| **🎯 Указка (Z-Поворот)** | Поворот корпуса телефона влево/вправо в горизонтальной плоскости (вокруг вертикальной оси Z) смещает куб по горизонтали. Наклон носа вверх/вниз регулирует высоту. | Основной режим фестиваля: ощущение «лазерной указки» или руля. Боковые наклоны ребер игнорируются. |
| **🕹 Ручной тачпад** | Интерактивный круговой радар на экране смартфона: игрок водит пальцем по тачпаду. | Для шумных условий, транспорта или пользователей, предпочитающих классический сенсор. |

   [ Смартфон Игрока ]                              [ Большой Экран / ПК ]
  (controller.html, JS)                             (index.html, Three.js)
           │                                                  │
 1. DeviceOrientation API                                     │
    (α, β, γ) 60 Hz                                           │
           │                                                  │
 2. Zero-Ref Z Math                                           │
    Δθ_z = -(α - α₀) mod 360                                  │

           │                                                  │
 3. Paho MQTT WebSocket                                       │
    Topic: flexy/motion/{PIN}                                 │
           │                                                  │

### 2.1. Сетевой транспорт (Zero-Install Cloud Broker)
Поскольку на фестивалях гости подключены к мобильному 4G/5G разных сотовых операторов (а не к единой локальной Wi-Fi сети), обмен данными построен на базе **MQTT over WebSockets (WSS)**:

1. **Библиотека**: `Eclipse Paho JavaScript Client` (`mqttws31.min.js`).
2. **Основной брокер**: `wss://broker.hivemq.com:8884/mqtt` (SSL).
3. **Резервный брокер (Auto-Failover)**: `wss://broker.emqx.io:8084/mqtt` (SSL). Если основной брокер недоступен или падает соединение, клиент мгновенно переключается на запасной без разрыва сессии для игрока.
4. **Структура топиков**:
   * `flexy/motion/{roomId}`: Канал координат движения (60 пакетов/сек, полезная нагрузка: `{"type":"motion","x":0.42,"y":-0.15}`).
   * `flexy/events/{roomId}`: Системный двусторонний канал (подключение, калибровка, тактильная вибро-отдача).

### 2.2. Математика гироскопа и отслеживание Z-ориентации
Главная техническая сложность в веб-гироскопах на смартфонах — предотвратить паразитное смещение от боковых наклонов и устранить конфликт систем координат браузеров.

1. **Единый поток событий**:
   * Используется строго стандартный `deviceorientation` (относительный датчик гироскопа/акселерометра).
   * Исключен компасный `deviceorientationabsolute`, чтобы избежать скачков ориентации от магнитных полей и перескоков между 2° и 105°.
2. **Калибровка нуля (Zero-Referenced Baseline)**:
   * При нажатии «Калибровать центр» сохраняются базовые углы $\alpha_0$ (рыскание) и $\beta_0$ (тангаж).
   * До момента калибровки координаты фиксируются строго в $(0, 0)$.
3. **Расчет чистого угла поворота вокруг оси экрана (Z-Axis Normal)**:
   Разница углов рассчитывается с корректной обработкой перехода через $0^\circ / 360^\circ$:
   $$\Delta\theta_Z = - ((\alpha - \alpha_0 + 540) \bmod 360 - 180)$$
   $$\Delta\theta_Y = (\beta_0 - \beta)$$
4. **Нормализация и мертвая зона**:
   $$X_{\text{norm}} = \text{clamp}\left(\frac{\Delta\theta_Z}{\text{MAX\_Z\_ANGLE}} \times \text{Sensitivity}, -1.0, 1.0\right)$$
   $$Y_{\text{norm}} = \text{clamp}\left(\frac{\Delta\theta_Y}{\text{MAX\_Y\_ANGLE}} \times \text{Sensitivity}, -1.0, 1.0\right)$$
   * $\text{MAX\_Z\_ANGLE} = 24^\circ$ — комфортный диапазон поворота кисти руки для полного прохода куба от левого до правого края экрана.
   * Ось $Y$ по умолчанию инвертирована для естественного ощущения управления авиацией/указкой.

### 2.3. Графический и физический движок (Three.js)

1. **Пространственная геометрия**:
   * Используется перспектива `THREE.PerspectiveCamera` с фиксированным полем зрения $\text{FOV} = 50^\circ$, выровненная по размеру игрового поля `RENDER_WIDTH = 1000` и `RENDER_HEIGHT = 1600`.
2. **Сглаживание движения (Linear Interpolation - LERP)**:
   * Чтобы куб двигался плавно даже при сетевых микрозадержках, позиция интерполируется каждый кадр:
     $$x_{t} = x_{t-1} + (x_{\text{target}} - x_{t-1}) \times 0.22$$
   * Дополнительно куб кренится в сторону поворота:
     $$\text{rot}_Z = (x_{\text{target}} - x) \times (-0.0015)$$
     $$\text{rot}_X = (y_{\text{target}} - y) \times 0.0015$$
3. **Физика препятствий (N-Body Repulsion)**:
   * Каждая пара падающих фигур в радиусе $R_{\text{repulsion}}$ испытывает отталкивающую силу:
     $$F = K \cdot \left(1 - \frac{d}{R}\right)^2 \cdot C_{\text{factor}}$$
   * Это предотвращает слипание объектов в неразрешимые стены и создает органичные волновые формации.
4. **Система детекции столкновений (Sphere Collision)**:
   * Для высокой производительности коллизии рассчитываются через быстрое расстояние радиусов сфер $d^2 \le (r_1 + r_2)^2$.
5. **Система частиц (Explosion Emitter)**:
   * При взрыве создаются 40 3D-фрагментов с индивидуальными векторами скорости, гравитацией, вращением и альфа-затуханием (`material.opacity`).

---

### 2.4. Мобильные оптимизации и безопасность
* **Screen WakeLock API**: Автоматически блокирует затухание/блокировку экрана телефона во время игры (`navigator.wakeLock.request('screen')`).
* **iOS Permission API**: Предусмотрен асинхронный запрос прав на доступ к датчикам движения для Safari на iPhone (`DeviceOrientationEvent.requestPermission()`).
* **Haptic Vibration API**: Тактильные импульсы (`navigator.vibrate([30, 40, 50])`) синхронизированы с игровыми событиями.
